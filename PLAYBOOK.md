# Fleet Playbook (strategy panel synthesis, 2026-08-31)

## Mission

Turn the four-bot fleet into a polite, latency-efficient survival economy that exploits three verified world facts: (1) the daylight cycle is frozen at day-0 morning, so beds/wool/night-prep are deleted from the roadmap and death always respawns at world spawn next to camp; (2) bot.blockAt() x-rays entire chunk columns, so ALL prospecting and branch mining is replaced by scan-then-tunnel to exact known coordinates (80 iron, 164 coal, 291 diamond ore already censused); (3) throughput is agent-latency-bound, so LLM drivers act as foremen who install generation-tokened JS macro loops via /eval while the orchestrator watchdogs heartbeats. Sequence: restart runners so safety plugins actually load -> surface iron -> 15-ingot 80/20 kits -> SW depot with labeled chests and 4-furnace bank -> penned herd + wheat -> one permanent staircase to the shallow diamond band at y-38..-45 -> diamond tier. Coordination runs over shared JSON files in /home/felix/minecraft/bots/shared/ (chests are ground truth); in-game chat is English narration plus human replies ONLY — it is data, never a command channel, and the fleet behaves as a guest on someone else's server (never attack players, never touch foreign property, honor claims, no retaliation against the drop-hoovering zetbots). Standing rules preserved throughout: stupid funny bot names, English chat narration, always equip best gear, never leave drops behind.

- The coordination bus is FILES, not chat: shared/base_manifest.json (placed coords), ledger.json (advisory chest contents), claims.json, chests.json (our containers), escalations.jsonl. A driver must reinstall the controller and verify the profile before assuming the bot is tasked; the orchestrator treats connected-without-ctl as ORPHANED and forces reinstall.
- Escalation ladder: L0 in-loop (3x retry then skip, auto-eat, flee, inventory-full haul, corpse-run queueing) — zero tokens; L1 driver re-plan (consume status.err + last 30 log lines); L2 orchestrator (restart/reassign on 3x same error in 10min, double WEDGED, or DOWN); L3 Felix ONLY for: gear lost at unknown coords, repeated deaths to one cause (possible griefing), server unreachable >10min, anything touching other players' property, server-admin needs, and any human chat request beyond stop/move/status. ## Orchestrator checklist

- Per bot every ~15s: poll GET /state plus the status /eval and issue exactly one verdict — DOWN (connection refused or stale pidfile -> stop.sh + spawn.sh), RECONNECTING (connected:false >2min while the MC port answers -> restart process), ORPHANED (connected:true but bot.ctl undefined, i.e. post-reconnect -> direct the driver to reinstall the controller AND verify the Movements profile), WEDGED (status 'running' but heartbeat age >15000ms -> gen++, setGoal(null), reinstall), STUCK (movement-implying task with <0.5 block position delta across 3 consecutive polls — NEVER applied to stationary guard duty -> driver re-plans with a different approach or site), STALLED (progress counter flat 60-120s during a work task -> driver investigates), ERRORED (status 'error' -> driver reads err + last 30 log lines and re-plans).
- Idle watchdog (the observed garden-gnome failure, not hypothetical): position moved <1 block AND bot.targetDigBlock null for 90s while tasked -> POST /stop, then re-task.
- Tail logs/<name>.log with matchers for <death>, <kicked>, <health> below 8, 'reconnect scheduled', <api-error>, <uncaught> — react to matches, never to silence (a quiet server is legitimately quiet).
- Death dispatch: on any death event record last-known coords from the controller's lastPos, assign the nearest free bot (default Bernd) a corpse run inside the 5-minute despawn window; forbid recovery into lava or deep water; log write-offs to escalations.jsonl.
- Etiquette sweep: (a) any human chat line unanswered >2min -> prod the addressed driver; (b) any bot exceeding 1.5 chat lines/min or the 45s spacing -> throttle its driver; (c) any bot position inside a foreign claim sphere per claims.json -> order it out immediately; (d) new escalations.jsonl entries -> dedupe same-kind within 30min and surface L3 items to Felix in-terminal plus one in-game mention.
- Economy audit: spot-check ledger.json against one physical chest per cycle (chest contents win; correct the ledger); verify GEAR still holds a spare kit + 8 food per bot; verify every driver's macro queue depth >=2 and no per-block LLM actions are occurring; count unmet category needs and empty-chest events as the standing bot-#5 gate metric.
- Standing-rules audit: narration is English and within rate limits; best gear is equipped (armorManager alive post-restart); the no-drops rule holds (loop stats: collected counts track dig/kill counts, YOINK losses logged not retaliated); any newly spawned bot has a properly stupid name BEFORE it connects.
- Safety config audit: confirm on every bot that allowSprinting=false, maxDropDown=3, allowParkour=false, allow1by1towers=false and the claims.json exclusion functions are live (they vanish on every reconnect until the runner.js patch is verified); confirm a water bucket is in inventory for any bot below y-30; confirm no bot is inside a natural cave; confirm torch spacing on active tunnels.
- Milestone gating: each iteration check the current milestone's DONE criteria and release the next only when met; whenever mining advances 32 blocks or a new area opens, trigger a fresh deep-scan and refresh the shared lava and ore coordinate sets before any driver plans a dig path.

## Automation guidance

Hybrid architecture: LLM foreman, injected JS muscle. Per-action LLM driving (one inference per swing, 5-30s visible idling) is reserved exclusively for novel situations, diagnosis, and social/chat handling — never production work. All production runs as injected bot.ctl macro loops installed via /eval using the canonical generation-token pattern (stored under /home/felix/minecraft/bots/shared/snippets/ as install-controller, cancel, and status-poll; drivers send them verbatim): gen++ cancels; alive() checked after every await; every long await wrapped in a timeout race; setGoal(null) and listener removal in finally; the eval returns immediately — fire-and-poll, never the held-open /goto. Paradigm per task: MINING = deterministic lane/staircase loop (dig head-then-feet forward; 6-neighbor lava check per dig plus r16 rescan every 32 blocks below y-30; item pickup within r6 immediately after each dig; food/tool-durability/empty-slot check every N blocks; LLM chooses lane coordinates from scan data and decides return trips). CHOP = SCAN nearest log -> goto -> fell bottom-up -> collect drops+saplings -> replant -> next; LLM re-tasks species/sector/delivery. HUNT = SCAN -> CHASE -> ATTACK -> COLLECT with ~625ms sword cadence, lookAt before each swing, and the player-entity guard as the first line of the attack path; always collect before the next target. HAUL = waypoint chest route; LLM handles exceptions only (chest full/missing/blocked). GUARD = must be fully in-process — 250ms hostile poll within r16, response in ticks not LLM turns; stationary by design, so exempt from all position-delta watchdogs. Self-care lives at L0 inside every loop (auto-eat at food<=16, flee toward the depot at hp<8, 3x retry then skip with stats.skips counted, inventory-full -> self-switch to a haul-home macro, death -> queue a corpse-run macro to recorded lastPos). Narration is emitted by the loop at phase transitions within the 45s/bot chat budget, so bots stay visibly alive while drivers think; drivers plan the NEXT macro while the current one runs and refill whenever the status poll shows queue<2. Prefer polling inside loops over bot.on listeners (leaked listeners across reinstalls cause double-actions); any unavoidable listener is stored on the controller and removed on cancel. Skip mineflayer-statemachine entirely — the hand-rolled c.state field provides the same visibility with zero dependency risk. Hard reconnect rule: runner.js builds a fresh bot object, so a connected:false->true transition means bot.ctl and (pre-patch) the Movements profile are GONE — reinstall both before treating the bot as tasked; the orchestrator's ORPHANED verdict enforces this.
