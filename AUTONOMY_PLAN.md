# Autonomy Plan (Baritone research panel synthesis, 2026-08-31)

Source: multi-model research workflow wf_e37e5adb-ab5 (full details in its journal).

## Chosen approach

Enhance the existing mineflayer runner as the primary autonomy stack, in three layers: (1) harden the current runner (strict task mutex, Paper/Spigot packet hardening vendored from mindcraft's mcdata.js, keep mineflayer-auto-eat at 3.3.6); (2) vendor mindcraft's MIT skill library (skills.js ~38 behaviors + world.js) into runner.js for crafting/smelting/chests/placing/dig-down/surface/defend, plus a ported subset of its background survival 'modes' (no LLM involved); (3) add @miner-org/mineflayer-baritone 4.6.2 as an opt-in second movement engine on bot.ashfinder behind a new /goto2 route, keeping mineflayer-pathfinder loaded as the default. Real Baritone IS feasible on 1.21.11 (track 1 verified the MeteorDevelopment fork jar for exactly 1.21.11 plus HeadlessMc 2.10.0 offline-headless launch) — run it ALONGSIDE the mineflayer suite, never instead of, and only as a deferred Phase-2 sidecar bot for long-haul travel/mining quality if mineflayer pathing provably becomes the blocker. INSTEAD OF is ruled out because mineflayer-pvp and mineflayer-collectblock are hard-welded to bot.pathfinder (track 2, PVP.js/CollectBlock.js source), the HTTP control surface needs mineflayer's programmatic state access which a JVM client lacks (chat-prefix commands only), and the JVM route costs ~1.5-2GB RAM per bot vs ~100MB.

## Why

Capability-to-fragility ratio. Every element of the primary path is verified on this exact box: track 2 require()-probed all plugins against mineflayer 4.38.0/Node 24.20.0 and validated 1.21.11 data (protocol 774, digTime/canHarvest/foods) via prismarine-registry; track 3 verified require(ESM) works on Node 24.20.0 so CJS runner.js can consume mindcraft's ESM skills directly, and verified runner.js's /autoeat uses the 3.x API; my own check confirms package.json/lockfile are now in sync and all five plugins already load. The real-Baritone path, while feasible (track 1's downloaded-and-inspected Meteor fork jar), carries three open unknowns (standalone '#' chat-prefix untested in-game, possible fabric-api dependency of hmc-specifics, snapshot-jar churn) plus a hard missing prerequisite (Java not installed at all) — right as an escalation, wrong as a foundation. Conflict rulings: (a) auto-eat — track 3 wins over track 2: stay on 3.3.6; 5.0.3 is ESM-only with a renamed API (loader/enableAuto/setOpts) that breaks runner.js's verified /autoeat route for zero capability gain, and mindcraft independently pins ^3.3.6; (b) mineflayer-statemachine — skip per track 2's three verified disqualifiers (ships a second Node runtime as a dependency, community-declared dead in issue #200, duplicates the HTTP sequencing model); (c) ashfinder — tracks 2 and 3 independently converge on adding it as a second engine, not a replacement, which is the strongest cross-track agreement in the panel; (d) mindcraft as a whole runtime — rejected as primary (LLM key, nondeterminism, socket.io-only control, Node-24 native-build breakage), but its MIT skill/hardening code is the cheapest capability multiplier available since it targets the exact plugin set already installed here.

## Fallback

Layered, in order. (1) If ashfinder misbehaves or crashes: stop routing to /goto2 — pathfinder remains the default engine and nothing else depends on ashfinder, so rollback is npm uninstall plus deleting one route. (2) If vendored mindcraft skills prove too entangled to stub cleanly: keep only the Paper hardening and the modes port (both small and self-contained) and reimplement the few needed behaviors (craft/smelt/chest) directly against mineflayer's own APIs. (3) If mineflayer movement/physics quality is provably the hard blocker: activate the Phase-2 real-Baritone sidecar (track 1's verified path: Meteor fork 1.21.11-SNAPSHOT + HeadlessMc 2.10.0, offline+headless) ALONGSIDE the fleet; within that path, if the Meteor fork misbehaves in-game, fall back to official Baritone v1.15.0 on a fabric:1.21.8 client with ViaVersion+ViaBackwards added to the Paper server so the older client can join. (4) Last resort only if per-bot resource cost or physics fidelity at swarm scale becomes the issue: azalea pinned at exactly 0.15.1+mc1.21.11 (Rust, offline auth first-class, built-in pathfinder with mining/parkour) — a full rewrite, modeled on ShayBox/ShaysBot's HTTP-API pattern.

## Risks

- Concurrency is the top operational risk: pathfinder, pvp, collectblock, and ashfinder are four independent control loops over one body (track 2, verified in source); without the strict 409-on-busy mutex and the ordered /stop cleanup, concurrent goals cause in-place jitter or cliff walks.
- ashfinder (@miner-org/mineflayer-baritone) is beta-grade: single maintainer, 20 releases in ~18 months, open crash issue #9, npm-says-ISC but no license file in the repo — pin --save-exact 4.6.2, wrap every goto in a timeout, and keep /goto (pathfinder) as the default so failure is a no-op, not a regression.
- The vendored mindcraft skills rely on Node >=22.12 require(ESM) interop; a Node downgrade on this box breaks the require() and needs await import() instead. The stubs (bot.interrupt_code, bot.modes, settings) may also miss edge paths — vet each skill function via /eval before giving it a route.
- auto-eat stays on 3.3.6 (last of the CJS line): if anyone bumps it to 5.x, the load line (plugin -> loader), the /autoeat route (enable/disable -> enableAuto/disableAuto), and the events all break silently at startup — pin it and comment why in package.json.
- 1.21.11 data quirks are silent: canHarvest returns null/undefined rather than false, and digTime is finite for non-harvesting tools — any hand-written tool logic without {requireHarvest:true} destroys ore with no drop (track 2, measured locally).
- Phase 2 unknowns (accepted because deferred): the Meteor Baritone fork's standalone '#' chat control is untested in-game, hmc-specifics may require fabric-api, the jar is a mutable -SNAPSHOT, and each JVM headless client costs ~1.5-2GB RAM; Java 21 is not currently installed at all.
- mineflayer-pathfinder itself is near-frozen upstream (npm 2.4.5 from 2023) — acceptable now, but it is the load-bearing dependency of pvp and collectblock, so its stagnation is the long-term ceiling of the primary stack.
- Minor: mineflayer-pvp drags in ~125MB of dead weight via abandoned mineflayer-utils (harmless at runtime); armor-manager ranks chainmail above iron (cosmetic downgrade).
